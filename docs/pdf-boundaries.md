# 문항 누락 진단과 보정

## 확인된 기존 코드의 제한

1. 기존 정규식은 `2.본문`처럼 마침표 뒤 공백 없는 표기, 독립 숫자 줄, 원형 번호를 인식하지 않았다.
2. PDF 중간을 가로지르는 단어가 한 개라도 있으면 2단 감지를 포기했다. 전체 폭 머리말이 있는 시험지가 영향을 받을 수 있었다.
3. 1단처럼 좌우 내용을 같은 줄에 합치면 오른쪽 문항이 먼저 보이거나 줄 중간에 번호가 나타날 수 있었다.
4. 작은 번호가 뒤늦게 나타나면 기존 코드가 이전 문항에 합쳤다. 연속 번호 누락 경고도 없었다.

이 제한은 코드와 생성 PDF로 재현한 원인이다. 사용자가 보고한 실제 PDF는 아직 제공되지 않아
그 파일의 2·5·7·9·11번이 텍스트 추출 단계에서 사라진 것인지 단정할 수 없다.

## v2 처리

- 번호와 본문 사이 공백 유무, 전각 숫자·마침표, `번`, 독립 번호 줄과 분리 토큰을 처리한다.
- 원형 번호는 실제 문항 번호인지 선택지인지 구분하기 어려우므로 기본적으로 제외한다.
  실제 문항 번호가 원형인 시험지는 UI의 원형 번호 모드를 선택한다. 좌표·문단 간격 검사도 적용한다.
- 단어 x/y 좌표로 줄을 만들고, 반복되는 넓은 중앙 여백에 투표해 2단을 감지한다.
  전체 폭 머리말 때문에 감지를 포기하지 않는다. 왼쪽 열 전체 다음 오른쪽 열 전체를 읽는다.
- 번호 후보의 열 시작점 정렬·들여쓰기·하단 위치·다음 본문 줄 거리를 검사한다.
- 자동 감지가 틀리면 업로드 화면에서 1단/2단 읽기 순서를 지정하고 새 추출을 실행할 수 있다.
- 추출 버전은 `pdfplumber-layout-v2`로 기록한다. 기존 추출본과 확정 문항은 자동 변경하지 않는다.

## 화면에서 진단하기

‘페이지별 추출 원문 보기’를 펼치고 ‘번호 탐지 진단’을 확인한다.

- 문자·단어가 0이면 텍스트층 없음/OCR 필요 가능성이다. 빈 페이지도 있을 수 있다.
- 기본 추출 텍스트에 번호가 있는데 좌표 후보에 없으면 토큰·줄 배치를 확인한다.
- 후보는 있으나 제외되었으면 들여쓰기·하단·독립 숫자 조건을 확인한다.
- 원래 번호 순서와 좌표 정렬 번호 순서가 다르면 2단 읽기 순서의 영향을 확인한다.
- 좌표 후보가 채택되었으나 문항으로 분리되지 않았다면 중복·역순 또는 내부 목록 번호를 확인한다.
- 번호가 보이지 않는다고 본문 전체가 추출되지 않았다고 단정할 수는 없다.
  숫자만 이미지일 수도 있고 폰트 매핑이 깨졌을 수도 있으므로 원본 PDF가 필요하다.

`document_pages.diagnostics`에는 기본 추출 텍스트, 문자·단어 수, 열 경계,
번호 순서와 줄별 좌표·채택 여부·이유가 저장된다. GET 추출 API의 `boundary_report`는
누락 번호별 증거와 가능한 원인을 요약한다.

## 보정과 저장

1. `1, 3`처럼 번호가 비면 1번과 3번 사이에 ‘2번 누락 가능’ 표시가 나온다.
2. 이전 문항에 2번 본문이 붙어 있으면 커서를 경계에 놓고 분리한다. 가능한 누락 번호를 먼저 제안한다.
3. 또는 ‘2번 누락 문항 추가’를 눌러 빈 후보를 만들고 원문에서 실제 내용을 옮긴다.
   이전 후보에서 옮긴 내용은 이전 후보에서 지워 중복을 피한다.
4. 번호·본문·출처 페이지를 확인하고 초안을 저장한다. 수정 후 누락 경고는 다시 계산된다.
5. 일부 문항만 의도적으로 저장하려면 번호 누락 확인 항목을 체크한다. API도
   `acknowledge_missing=true` 없이 누락 번호가 있는 결과를 저장하지 않는다.

누락 표시가 실제 누락을 확정하는 것은 아니다. 부분 PDF나 문항 번호가 1부터 시작하지 않는
시험지일 수 있다. 마지막 문항 뒤 누락은 총 문항 수를 모르므로 자동 탐지하지 않는다.
원문이 없는 문항을 자동 생성하거나 내용을 추측하지 않는다. 새 빈 후보에도 원본 참조가
유지되고 출처 페이지 범위 검증을 적용한다. 저장된 문항은 이 화면에서 자동 교체하지 않는다.

실제 시험지의 수식·표·비정형 여백·스캔 혼합에서는 여전히 직접 검수가 필요하다.
