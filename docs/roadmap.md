# 개발 단계

## Phase 1 — 구현됨

FastAPI / SQLAlchemy / Alembic 기반 데이터 API. 시험과 PDF 문서의 다대다 연결,
문항별 다중 페이지 출처, 사상가·개념 마스터와 별칭 정규화, 계층 순환 방지,
분석별 사상가·개념·유형 연결, 근거 구분, 수정 리비전과 검수 이벤트,
문항별 확정본 선택을 구현한다. PostgreSQL과 개발용 SQLite를 지원한다.

Phase 1에서는 분석 입력 API를 제공한다. LLM을 실제로 호출하거나 원문에서 분석을
자동 생성하지 않는다. 저장하는 분석의 진실성은 사용자 검수가 담당한다.

## Phase 2 — 구현됨

FastAPI와 같은 서버에서 제공하는 HTML/CSS/JavaScript 검수 UI. PDF 업로드·SHA256 중복 감지,
pdfplumber 페이지별 추출, 보수적 2단 감지와 순차 번호 기반 문항 후보 분리,
추출 실행·페이지·원본 후보·수정 후보 보존. 화면에서 문항 내용·번호·출처 페이지 수정,
합치기·커서 위치 분리, 초안 재접속, 문항 DB 저장. 스캔은 needs_ocr, 혼합 문서는 partial.
직접 생성한 PDF로 API와 실제 Chromium 브라우저 전체 흐름을 검증한다.
작업 큐, OCR, 모든 PDF 레이아웃에 대한 완벽한 분리는 아직 제공하지 않는다.

## Phase 3

LLM provider 인터페이스, JSON Schema 강제 출력, 분석 실행 테이블,
프롬프트·스키마 버전과 입력 해시, 재시도 및 비용 기록. 미등록 명칭 후보 검토.

## Phase 4

AI 분석 검수 UI 확장(필요 시 Next.js 도입), 사용자 인증·권한, 검수자 ID와 변경 내역 감사,
PDF 원본·문항·분석 비교, 최신 리비전 및 확정본 충돌 처리.

## Phase 5

현재 확정본만 집계하는 SQL 통계, 기간 필터, 사상가·개념·영역·유형 분석,
공동 출제·고유 연도 기준 출제 간격, 수록·검수 완료율과 분모 표시.
샘플과 실제 시험 데이터의 명시적인 구분 필드를 이 단계 전에 추가한다.

## Phase 6

통계 스냅샷과 버전별 공부 우선순위 정책, 코드 기반 등급 계산,
계산 지표에 근거한 AI 설명 및 데이터 부족 표시.

원전 RAG, OCR/이미지 입력, 개인 학습 기록 및 예상문제 생성은 MVP 이후로 분리한다.

## 이미지 기반 처리 전환 — 구현됨

PDFium 페이지 PNG 렌더링, 재사용 가능한 페이지 자산·영역, 구조화 후보·배치·작업 테이블,
MultimodalExtractionProvider와 명시적인 Mock Provider, 좌우 원본/검수 UI를 추가했다.
Mock은 페이지별 임시 후보를 만들며 실제 AI 문항 분리나 OCR을 수행하지 않는다.
선택지·출처 영역은 일반 폼과 원본 드래그로 수정하고, 검토 후 기존 Question DB에 저장한다.
기존 pdfplumber 경계 탐지는 보조 모드로 유지한다. Windows 원클릭 시작과 Render/Docker,
PostgreSQL·Redis worker·S3 저장소 인터페이스를 준비했다. 외부 LLM과 실제 공개 배포는 미실행이다.
