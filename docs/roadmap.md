# 개발 단계

## Phase 1 — 구현됨

FastAPI / SQLAlchemy / Alembic 기반 데이터 API. 시험과 PDF 문서의 다대다 연결,
문항별 다중 페이지 출처, 사상가·개념 마스터와 별칭 정규화, 계층 순환 방지,
분석별 사상가·개념·유형 연결, 근거 구분, 수정 리비전과 검수 이벤트,
문항별 확정본 선택을 구현한다. PostgreSQL과 개발용 SQLite를 지원한다.

Phase 1에서는 분석 입력 API를 제공한다. LLM을 실제로 호출하거나 원문에서 분석을
자동 생성하지 않는다. 저장하는 분석의 진실성은 사용자 검수가 담당한다.

## Phase 2

PDF 파일 저장소, 파일 검사, 추출 작업·페이지 테이블, 문항 분리 후보 및 추출 검수.
다단 편집·다중 페이지 문항 대표 PDF로 검증. 스캔은 needs_ocr로 표시.

## Phase 3

LLM provider 인터페이스, JSON Schema 강제 출력, 분석 실행 테이블,
프롬프트·스키마 버전과 입력 해시, 재시도 및 비용 기록. 미등록 명칭 후보 검토.

## Phase 4

Next.js 검수 UI, 사용자 인증·권한, 검수자 ID와 변경 내역 감사,
PDF 원본·문항·분석 비교, 최신 리비전 및 확정본 충돌 처리.

## Phase 5

현재 확정본만 집계하는 SQL 통계, 기간 필터, 사상가·개념·영역·유형 분석,
공동 출제·고유 연도 기준 출제 간격, 수록·검수 완료율과 분모 표시.
샘플과 실제 시험 데이터의 명시적인 구분 필드를 이 단계 전에 추가한다.

## Phase 6

통계 스냅샷과 버전별 공부 우선순위 정책, 코드 기반 등급 계산,
계산 지표에 근거한 AI 설명 및 데이터 부족 표시.

원전 RAG, OCR/이미지 입력, 개인 학습 기록 및 예상문제 생성은 MVP 이후로 분리한다.
